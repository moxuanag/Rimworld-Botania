## 1. 建材盖出来的东西中英混排：「dreamwood 墙」

**日期**：2026-10-23（实装梦木 / 元素锭时踩到）

**现象**：用梦木、元素锭盖的墙显示成 `dreamwood 墙`、`elementium 墙`；
活木墙、魔力钢墙一直正常。

**原因**：带材料的物品名字由 `Thing.LabelNoCount` 拼：

```csharp
stuff.LabelAsStuff + " " + def.label
```

而 `ThingDef.LabelAsStuff` 直接返回 `stuffProps.stuffAdjective` 的**原文**，
不经过 Def 的 label 翻译。所以 `label` 翻译了也没用，`stuffAdjective` 必须单独注入。

**定性做法**：凡是写了 `<stuffAdjective>` 的建材，都要在
`Languages/ChineseSimplified (简体中文)/DefInjected/ThingDef/Botania_Things.xml`
里补一条：

```xml
<Botania_Dreamwood.stuffProps.stuffAdjective>梦木</Botania_Dreamwood.stuffProps.stuffAdjective>
<Botania_ElementiumIngot.stuffProps.stuffAdjective>元素</Botania_ElementiumIngot.stuffProps.stuffAdjective>
```

**防复发**：`_dev/_botania-dev/validate_mod.py` 的 `check_stuff_adjectives()`：
凡是带 `stuffAdjective` 的模组 ThingDef，中文缺注入直接 FAIL 并点名。
（已自测过：删掉元素锭那条会立刻报出来。）

## 2. 科技蓝图的整条链路都挂在皇权 DLC 上

**日期**：2026-10-23（实装盖亚之魂蓝图时确认）

**现象**：没装皇权 DLC 时，蓝图右键没有任何选项，等于一张废纸。

**原因**：三处 DLC 门，反编译逐一确认：

```csharp
// 1) 菜单入口
if (!ModLister.CheckRoyalty("Techprint")) yield break;      // CompTechprint.CompFloatMenuOptions
// 2) 真正的应用逻辑
if (!ModLister.CheckRoyalty("Techprint")) return;           // ResearchManager.ApplyTechprint
// 3) 结束时的音效：TechprintApplied 定义在 Royalty/Defs/SoundDefs/UI_OneShots_Misc.xml
SoundDefOf.TechprintApplied.PlayOneShotOnCamera();          // 没装时为 null → NRE
```

**定性做法**：**不要用 Harmony 去补这三处**（补一处就得补一串，还会剩下 null 音效），
改成自己写一条干净的路：`Source/CompBotaniaBlueprint.cs`，只在
`ModsConfig.RoyaltyActive == false` 时提供右键「解读蓝图」，内部直接调
`ResearchManager.AddTechprints(proj, 1)`；有皇权时它自动沉默，菜单仍归原版。

**顺带记住**：`heldByFactionCategoryTags` 在这套引擎里**只是一个字符串列表**，
没有 `FactionCategoryDef` 类型、没有代码解析（只有 `ResearchProjectDef.ConfigErrors`
检查空/非空），所以随便填个表意名字即可，不会真的去匹配派系。
但它必须和 `techprintCount` **成对出现**，否则直接配置错误。

## 3. 自定义 JobDef + JobDriver 不生效

**日期**：早于本文档（见技能手册「关键结论表」）

**现象**：写了 JobDef + JobDriver，想让小人「走过去再做事」，游戏里毫无反应。

**定性做法**：这套引擎不支持自定义作业。要「走过去」就用
`JobMaker.MakeJob(JobDefOf.Goto, cell)`，或者干脆不做、只提示「超出范围」。
所以需要「耗时动作」时，宁可退成即时生效（如 §2 的蓝图解读）。

## 4. XML 标签错配只报行号，查起来很慢

**日期**：2026-10-23（写 `Items_Botania_Elven.xml` 时把 `</WorkToMake>` 写成 `</WorkToBuild>`）

**现象**：`validate_mod.py` 报 `mismatched tag: line 134`，但不说是哪个标签。

**定性做法**：用 `_dev/_botania-dev/_check_xml_balance.py`，它会打印
「行 N：`</A>` 与行 M 的 `<B>` 不匹配」，直接给出两个标签名。

## 5. 贴图不是「画出来就能用」：护甲披挂图必须带体型

**日期**：2026-10-23（生成护甲贴图时确认）

**现象**：准备了 `_south / _north / _east` 三张披挂图，但引擎拼出来的路径对不上。

**原因**：

```csharp
path = apparel.WornGraphicPath + "_" + bodyType.defName;   // 先拼 _Male / _Female / _Thin ...
GraphicDatabase.Get<Graphic_Multi>(path, ...);             // 再拼 _south / _north / _east
```

真名形如 `Botania_ElementiumArmor_Male_south.png`，5 种体型 × 3 方向 = 15 张/件。

**定性做法**：这一版**不做披挂图** —— 只要 Def 里不写 `wornGraphicPath`，
`ApparelGraphicRecordGetter` 就返回 false，穿上没有任何外观变化，**且不报错**。
画好的三向图暂存在 `_dev/_botania-dev/_stash/worn_v07/`，
`gen_textures_v07.py` 里留了 `WORN_ENABLED` 开关。
