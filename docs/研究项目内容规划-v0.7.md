## 0. 原版内容 → 本模组：保留什么、砍什么

先把话说死，免得做着做着跑偏。原版 Botania 有大量内容**不适合**直接搬，理由是环世界没有对应系统。

| 原版 | 我们的处理 | 理由 |
|---|---|---|
| Flügel Tiara（真自由飞行） | **砍成跳跃挂饰**（已定，§5.3） | 自由飞行会让袭击的接近路线与地形系统失效 |
| Mana Diamond / Mana Pearl | **改用「魔力玻璃钢」** | 环世界没有钻石/珍珠产业链；玻璃钢有直觉（决策 14） |
| Corporea 请求/物流网络 | **不做** | 环世界有搬运与库存系统，重复 |
| 符文祭坛（合成符文） | **符文改购买 / 遗迹挖掘**（决策 10） | 砍掉一条合成链，稀有感来自探索 |
| 小精灵（Pixie）实体 | **不做实体，只做伤害演出** | 环世界加飞行小怪不值当 |
| Botanical Brewery（酿药） | **不做** | 原版药物系统已够用 |
| 花之力「无限耐久」 | **不做耐久概念** | 环世界装备走 HP + 魔力修补（§10） |
| 花瓣祭坛的合成花 | **保留**（v0.5 已实装花瓣祭坛） | 已是本模组的核心循环 |

留下来的主干，恰好就是剩下这 4 个研究：**精灵门（材料跨越）→ 元素装备 → 泰拉钢 → 盖亚（终局）**。

## 1. `Botania_Alfheim` 精灵之门（E3 · 3500 · 前置「魔力灌注」）

**这一版要回答的问题**：魔力能不能换来「买不到的东西」。
原版的 Alfheim 门是一个「投料 + 魔力 → 精灵材料」的兑换口，我们照这个做。

> **2026-10-23 定稿并实装**，与初稿的三处改动见每节末尾的「改了什么」。

### 解锁清单

| 内容 | 类型 | 说明 |
|---|---|---|
| 精灵门 | 结构（三件套，总占 5×3） | 上梁 3×1 + 左柱 1×3 + 右柱 1×3，门洞 3×2 **真的留空、可通行** |
| 梦木 Dreamwood | 材料 | 活木的高阶版：深色、可做精灵门框架与高档家具/地板 |
| 精灵石英 Elven Quartz | 材料 | 水晶类，门上的透镜、魔力设施的高级部件 |
| 精灵之尘 Pixie Dust | 材料 | 元素锭的必要成分，也可做「精灵灯」 |
| 元素锭 Elementium | 材料 | 元素装备的唯一主料（对应原版 Elementium Ingot） |

### 运作方式

- **投料自动转化**：把材料丢进门洞里，门自己从附近魔力池抽魔力，转够时间吐出成品；
- 不需要派人干活，也不需要打开 Bill 面板；
- **硬性要求魔力**：没有池子、或池子不够，就停在原地等，进度保留，绝不「免魔慢转」；
- **门框必须完整**：少一根柱子完全不工作，检视栏直接写「门框不完整」；
- 上梁可以「精灵门开关」暂停。

### 数值（已实装）

| 转化 | 输入 | 魔力 | 耗时 |
|---|---|---|---|
| 梦木 ×1 | 活木 ×4 | 200 | 600 tick（10 秒） |
| 精灵石英 ×1 | 活石 ×4 | 200 | 600 tick（10 秒） |
| 精灵之尘 ×1 | 任意花瓣 ×2 | 100 | 300 tick（5 秒） |
| 元素锭 ×1 | 魔力钢 ×2 + 精灵之尘 ×1 | 300 | 1800 tick（30 秒） |

> 元素锭刻意比其它三种慢三倍：它是装备主料，不该和普通材料同速。
> 魔力在**完成那一刻**一次性扣；中途把材料搬走则进度作废（防止「搬走再放回」刷进度）。

建造材料（合计）：魔力钢 ×16 + 活木 ×20 + 活石 ×10 + 部件 ×2。

### 实现要点

- Def：`Defs/ThingDefs_Buildings/Buildings_Botania_AlfheimGate.xml`（3 个 ThingDef）；
- 逻辑：`Source/CompManaGate.cs` + `Source/PlaceWorker_GateFrame.cs`；
- 转化规则挂在**上梁**的 `CompProperties_ManaGate` 上，立柱只提供「门框完整」这个条件；
- 找魔力源复用 `ManaSourceUtil.FindNearest`（和花、中继塔同一套网络）；
- 放置时用 `PlaceWorker_GateFrame` 把两根柱子的位置用绿框标出来。

### 改了什么（相对初稿）

1. **Bill → 投料自动转化。** 这套引擎没有干净的「Bill 扣魔力」接入点
   （`RecipeDef` 不认魔力，而自定义 JobDriver **实测不生效**），
   硬做只能每 tick 扫「谁在这个台子上干活」，太脆。改为复用白雏菊那套转化思路，
   但重写成 `CompManaGate`：白雏菊的「断魔降速免魔」语义对门是错的，门必须停。
2. **5×3 实心 → 三件套真门洞。** 环世界的 `size` 是实心矩形，没法在 5×3 里挖洞。
   拆成上梁 + 左右柱之后，中间 3×2 是真空地，人能走过去，也更像门。
3. **精灵石英的输入从「玻璃 ×4」改成「活石 ×4」。** 环世界根本没有玻璃这个物品
   （`defName` 里一个都搜不到），原来的配方式立刻卡死；活石是白雏菊就能产的东西，
   且「把石头养成水晶」在设定上更顺。
4. **建造材料改掉循环依赖。** 初稿要「梦木 ×12 + 精灵石英 ×8」，而这两样正是门的产品，
   等于要求先有门才能建门。改成全部来自门之前的科技。

## 2. `Botania_Elementium` 元素装备（E3 · 3000 · 前置「精灵之门」）

**这一版要回答的问题**：精灵材料做出来的东西，值不值这一整套产线。
原版 Elementium 是「粉色元素金属」，主打元素武器、护甲和小精灵演出。我们保留数值，砍掉实体精灵。

### 解锁清单

| 内容 | 类型 | 数值 |
|---|---|---|
| 元素剑 | 近战 | 26 伤害 / 35% 穿透 / 2.0s |
| 水晶弓 | 远程 | 16 伤害 / 射程 30 / 2.2s / 吃魔力不烧箭 |
| 元素甲 | 护甲（躯干+四肢） | 锐器 90% / 钝器 45% |
| 元素头盔 | 护甲（头） | 锐器 54% / 钝器 27% |
| 精灵灯 | 建筑 | 不用电的灯：耗魔力不耗电，见下 |

- **元素剑的「小精灵」**：原版是命中时放出小精灵追着咬。我们改成**命中时 20% 概率追加一次 8 点伤害**，
  单独弹一条伤害数字，纯演出向、不改变 DPS 量级；
- **水晶弓**：原版的元素弓带连锁。我们只保留「吃魔力不烧箭」——这条已经在法杖上验证过，复用 `CompManaWeapon`；

### 精灵灯（已定）

加它的理由：否则这个 3000 点的研究只给三件武器护甲，玩家会觉得亏；而且精灵石英需要第一个「看得见」的用途。

| 项 | 数值 |
|---|---|
| 建造 | 精灵石英 ×2 + 精灵之尘 ×1 + 魔力钢 ×2，占 1 格 |
| 光照 | 亮度与半径等同原版标准灯，**不耗电** |
| 美观 | +8 |
| 代价 | 从魔力网络抽 **1 魔力 / 60 秒** |
| 断供 | **直接熄灭**（不报错、不损坏；来魔力后自动亮回来） |
| 卖点 | 环世界的灯都要电，精灵灯不要 —— 风不稳、野外出击、无电前哨都能用 |
| 实现 | 纯 `ThingDef` + 原版 `CompProperties_Glower`，耗魔走现有魔力网络 Comp |

### 实现要点

- 三件武器护甲全是 `ThingDef`，无新代码（元素剑的追加伤害用一个 `HediffComp` 或 `DamageWorker` 覆盖）；
- 水晶弓复用现有 `CompManaWeapon` + `Verb_ManaBolt` 那套，只换数值；
- 精灵灯只是一个 `ThingDef` + 光源 Comp。

**护甲外观（2026-10-23 已定：先不做披挂图）**

反编译 `RimWorld.ApparelGraphicRecordGetter` 确认了两条硬规则：

```csharp
// 1) wornGraphicPath 留空 → 直接不画外观，不报错、也不退回物品图标
if (apparel.WornGraphicPath.NullOrEmpty()) { rec = new ApparelGraphicRecord(null, null); return false; }

// 2) 要画的话，真实文件名必须带体型与方向
path = apparel.WornGraphicPath + "_" + bodyType.defName;   // 例：_Male
GraphicDatabase.Get<Graphic_Multi>(path, ...);             // 再拼 _south / _north / _east
```

- 所以这一版**不写 `wornGraphicPath`**：护甲穿在身上没有任何外观变化，但绝不报错；
- 物品图标照常有（`graphicData.texPath`）；
- 以后要补外观，得按 `_Male/_Female/_Thin/_Fat/_Hulk` × 三向出图，
  不是三个文件而是最多十几个 —— 这就是本次先跳过它的原因。

### 4.2 盖亚之魂（科技蓝图）怎么拿

**2026-10-23 改定：由盖亚守护者（Boss）掉落。** 原先定的「遗迹挖掘」作废。

| 途径 | 状态 | 说明 |
|---|---|---|
| 盖亚守护者掉落 | **唯一途径** | Boss 实装后接上；打死守护者拿蓝图，用蓝图点开研究 |
| 遗迹挖掘 | **不做** | 曾经定过，现已取消，免得两条终局入口互相稀释 |
| 商人 | 不做 | 终局蓝图不该能用钱解决 |

Boss 还没实装，所以**当前版本蓝图没有实际来源**，只能在开发者模式刷出来测试，
`Botania_Gaia` 在正常游戏里暂时无法完成。不影响其他研究，Boss 落地时一次接通。

实现口径（**必须成对写**，否则引擎直接报配置错误）：

```xml
<!-- ResearchProjectDef -->
<techprintCount>1</techprintCount>
<heldByFactionCategoryTags>
  <li>BotaniaGaiaBoss</li>
</heldByFactionCategoryTags>
```

- 引擎的成对校验（`ResearchProjectDef.ConfigErrors`，已反编译核对，2026-10-23）：
  - `techprintCount > 0` 而 `heldByFactionCategoryTags` 为空 →
    `requires techprints but has no heldByFactionCategoryTags.`
  - `techprintCount == 0` 而写了 tags →
    `requires no techprints but has heldByFactionCategoryTags.`
  - 结论：两个字段必须**成对出现**，只能一起加、一起删；
- tags 里写什么：**这套引擎里它只是一个字符串**（没有 `FactionCategoryDef` 类型，
  也没有任何代码解析它；反编译确认只有空/非空的校验），填 `BotaniaGaiaBoss`
  表意即可，不会真去匹配派系，也就不会变成商人货架上的东西；
- 蓝图 ItemDef 挂**两个** comp：
  - `CompProperties_Techprint { project: Botania_Gaia }` —— 数据层，
    `ResearchProjectDef.Techprint` 靠反查它找到蓝图物品，
    缺了会 `Log.ErrorOnce: Could not find techprint for research project`；
  - `Botania.CompProperties_BotaniaBlueprint { project: Botania_Gaia }` —— 交互层，
    只在**没装皇权 DLC** 时提供右键「解读蓝图」，见 §8.3。

> 这一条是「蓝图要存在」的落地保证：先有物品，再谈 Boss。

### 4.1 盖亚守护者 · 攻击方式设计稿（讨论定稿，未实装）

分两个阶段，靠 HP 阈值切换；环世界没有多阶段实体，阶段差异只能靠「数值 + 挂 Hediff 表现」。

#### 阶段一（100% → 50%）

| # | 攻击 | 数值 | 冷却 | 对应原版 |
|---|---|---|---|---|
| 1 | 近战重击 | 40 伤害 / 范围 1.5 | 2.5s | Guardian 的横扫 |
| 2 | 精灵弹幕 | 3 连发，每发 12 伤害，射程 20 | 7s | 魔法弹 |
| 3 | 召唤小精灵 | 召 2 只，场上最多 4 只；小怪 15 伤害 / HP 200 / 移速 4.8 | 15s | 召唤 Pixie |
| 4 | 领域压制 | 半径 8 内**远程攻击伤害 −20%** | 常驻光环 | 原版的压迫感；环世界特有用法 |

- **第 4 条是专门为环世界加的**：没有它，玩家只要拉远距离用狙击型法杖就能白嫖；
  有了它，Boss 战必须准备近战/爆破两套方案。

#### 阶段二（HP < 50%）

| # | 变化 | 数值 |
|---|---|---|
| 5 | 上面的攻击**冷却全部 ×0.75** | — |
| 6 | **瞬移**：跳到 8~12 格随机位置 | 20s |
| 7 | **魔力爆裂**：瞬移落点留 3 格地面，3 秒后炸 25 伤害 | 跟着瞬移走 |
| 8 | **抗性**：锐器伤害 −30% | 常驻 |

- 第 6+7 条配套使用：瞬移走后原地不再是安全区，玩家得跟着挪位；
- 第 8 条逼玩家在打 Boss 前准备钝器或爆破型法杖，而不是一把近战砍到底。

#### 掉落

| 次数 | 掉落 |
|---|---|
| 首次击杀 | **盖亚之魂**（= 解锁 E4 的 techprint）+ 泰拉钢锭 ×2 |
| 之后 | 泰拉钢锭 ×2（不再掉蓝图，防刷） |

> Boss 落地之前，蓝图走遗迹挖掘（§4.2），不必等这套战斗做完。

#### 召唤条件（沿用 §11）

盖亚祭坛（3×3）+ 50,000 魔力 + 1 泰拉钢锭；仅夜间或雷暴可召唤（强化仪式感）。

#### 实现路径（实施前要用反射核对）

| 需求 | 打算怎么做 | 要核对的点 |
|---|---|---|
| 本体 | `PawnKindDef` + `ThingDef`（Race） | 引擎是否支持 `PawnKindDef.abilities` 直接挂能力 |
| 弹幕 / 瞬移 / 召唤 | 原版 `AbilityDef` | 1.7 的 Ability 系统给敌人怎么授予（PawnKind 字段 vs HediffComp） |
| 领域压制 | 给范围内小人挂负面 `HediffDef` | 得用 `statOffsets` 影响 `RangedWeapon_DamageMultiplier` 之类 |
| 魔力爆裂 | `ThingDef` + 延迟爆炸 Comp | 参考原版地雷 / 燃烧弹的实现 |
| 阶段切换 | 常驻 `HediffDef` + 检查 HP 比例 | 引擎里 Pawn 的 tick 钩子（`Tick` 覆写 vs Comp） |

> 风险最高的就是这块：Boss 手感、召唤平衡、存档兼容都要单独测。这也是先延后的原因。

### 8.2 建材前缀显示成英文（已修）

现象：梦木、元素锭盖出来的墙显示「dreamwood 墙」「elementium 墙」，
中英混排；而活木墙、魔力钢墙一直是正常的。

原因：建筑的带料名字由 `Thing.LabelNoCount` 拼 `stuff.LabelAsStuff + " " + def.label`，
`LabelAsStuff` 直接返回 `stuffProps.stuffAdjective` 的**原文**，不走 Def 的 label 翻译。
所以 `stuffAdjective` 必须单独在 `DefInjected/ThingDef/` 里注入中文：

```xml
<Botania_Dreamwood.stuffProps.stuffAdjective>梦木</Botania_Dreamwood.stuffProps.stuffAdjective>
<Botania_ElementiumIngot.stuffProps.stuffAdjective>元素</Botania_ElementiumIngot.stuffProps.stuffAdjective>
```

活木 / 魔力钢 / 活石早就写过（`活木` / `魔力钢` / `活石`），这次两种新材料漏了。

**防复发**：`validate_mod.py` 新增 `check_stuff_adjectives()` —— 凡是带
`stuffProps.stuffAdjective` 的模组 ThingDef，中文缺注入就判 FAIL，
并直接点名是哪个 Def。（已自测：删掉元素锭那条会立刻报出来。）

### 8.3 无皇权 DLC 时的蓝图解锁方式

原版这条路整条都挂在皇权 DLC 上，反编译确认有两处门：

```csharp
// CompTechprint.CompFloatMenuOptions 第一行
if (!ModLister.CheckRoyalty("Techprint")) yield break;
// ResearchManager.ApplyTechprint 第一行，同样的检查
if (!ModLister.CheckRoyalty("Techprint")) return;
// 而且 JobDriver_ApplyTechprint 结束时用 SoundDefOf.TechprintApplied，
// 那个 SoundDef 定义在 Royalty/Defs/SoundDefs/ 里，没装时为 null，直接 NRE
```

**为什么不用 Harmony 补掉那行**：门不止一处，补完菜单还要补 `ApplyTechprint`，
补完还要躲那个 null 音效，补一串下来比写一条自己的路更脆。

**实际做法**：新增 `Botania.CompBotaniaBlueprint`（`Source/CompBotaniaBlueprint.cs`），
挂在蓝图物品上，只在 `ModsConfig.RoyaltyActive == false` 时给右键菜单：

| 情况 | 菜单 | 行为 |
|---|---|---|
| 已解读过 | 「解读蓝图（盖亚）: 已经解读过」灰显 | — |
| 殖民者不能做智力工作 | 灰显「无法进行智力工作」 | — |
| 够不着物品 | 灰显 `CannotReach` | — |
| 正常 | 「解读蓝图（盖亚）」 | 调 `ResearchManager.AddTechprints(proj, 1)`，给 500 智力经验，播消息，销毁蓝图 |

- 有皇权时本组件**完全沉默**，菜单仍由原版 `CompTechprint` 提供，不会出现两个选项；
- 不做成「走过去、在台子前读 600 tick」：这套引擎里自定义 `JobDef + JobDriver`
  实测不生效（见开发笔记），所以退成即时解读；
- 数据层仍由 `CompProperties_Techprint` 负责，`ResearchProjectDef.Techprint` 能正常反查到物品。
