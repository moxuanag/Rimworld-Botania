# 丰饶花 · 扫描与种植规则（权威规格）

> 版本：2026-11-27 定稿（v1）
> 适用对象：`Botania_FertilityFlower`（`CompFertilityFlower`）
> **本文件地位**：凡与代码实现、历史讨论、子代理设想冲突，一律**以本文件为准**。
> 任何改动本文件的行为都必须由用户明确批准；子代理动手前必须先完整读本文件。

---

## 0. 一句话

丰饶花按**固定编号**逐格推进：判定（短路与）→ 割除 → 同格种植；走完一轮后处理升级回扫；
之后进入**每 3 游戏小时一次**的弱扫描（收完再补种，补种后再回扫不可种格）。

---

## 1. 编号（R1）

- **R1.1 触发重新编号的时机（三处，且每一处都要立刻执行，不等周期）**
  1. 建造完成（含**重新安装**：从可收纳物品放回地面）；
  2. 进阶功能花研究（`Botania_FuncAdvanced`）完成、半径 +1 时；
  3. 终极功能花研究（`Botania_FuncUltimate`）完成、半径再 +1 时。
- **R1.2 编号方式**：当前有效半径内的每一格，按 **z 从大到小（屏幕从上到下）**，
  同一行内 **x 从小到大（从左到右）**，编号 `1 … N`。
- **R1.3** 编号是**种植顺序**的唯一依据；主扫描按编号递增推进。
- **R1.4** 编号随存档保存（含每格坐标），弱扫描要用它做「范围是否一致」的比较。

## 2. 单格判定（R2，短路与）

对编号 `i` 的格子，按顺序判断；**任一条件不满足 → 标记该格「不可种」→ 直接跳到 i+1**，
不做任何割除/种植动作。

| 顺序 | 条件（必须满足） |
|---|---|
| R2.1 | 该格**地形可种植** |
| R2.2 | 该格上**没有建筑** |
| R2.3 | 该格上**没有树** |
| R2.4 | 该格上**没有人工种植的植物**（`Plant.sown == true`，含玩家种的、本花自己种的） |

- **R2.5 全部满足时**：先**割除**该格上的植物（含草、野花、野果灌木、**野生作物**），
  然后**在同一 tick、同一格**种下当前选定的作物，然后推进到 `i+1`。
- **R2.6 割除的产物**：被割除的植物若有产出（已成熟、有 `harvestedThingDef`），
  按**当前档位系数**（见 R7.2）折算产量并掉在花脚下；草/无产出植物不掉东西。
- **R2.7 割除必须真的清空该格**：不能使用「收获后回退成长度」的收尾方式；
  清完若该格仍被植物占着，该格按「不可种」处理（标记后跳过）。

## 3. 主扫描（R3）

- **R3.1** 按编号 `1 → N` 逐格执行 R2。
- **R3.2** 走到第 `N` 格即视为「一轮走完」；**第 N 格不可种也照常结束**。
- **R3.3** 但如果第 `N` 格**可种**，则必须**把这一株种完**才进入 R4（不允许半途切走）。

## 4. 一轮结束后的升级处理（R4）

- **R4.1** 检查档位是否升级（一档 → 二档 → 三档，判据为研究完成状态）。
- **R4.2 若升级**：回扫两类格子，逐个按 R2 判定：
  1. **之前被标记为「不可种」的格子**；
  2. **半径变大后新增的格子**；
  可种则按 R2 种植、不可种则标记并跳下一个；两类都过完一遍为止。
- **R4.3** 回扫结束后，**按新范围重新编号**（R1.2）。
- **R4.4** 若未升级：不做回扫，直接进入弱扫描（R5）。

## 5. 弱扫描（R5）

- **R5.1 周期**：每 **3 游戏小时 = 7500 tick** 执行一次（1 游戏小时 = 2500 tick，1 天 = 60000 tick）。
- **R5.2 先比较范围**：当前有效范围（中心 + 半径对应的格集合）与上次编号时是否一致。
  - **不一致** → 重新编号（R1.2）并**回到主扫描**（R3）；
  - **一致** → 继续 R5.3。
- **R5.3 逐格检查可收获**：按编号 `1 → N`，检查该格植物是否**生长完成（100%、面板显示可收获）**；
  可收获则收获，否则看下一格；直到 `N`。**这一遍只收，不补种。**
- **R5.4 收完之后回头补种**：把这一遍里被收获腾空的格子、以及当前为空且可种的格子补种上。
- **R5.5 补种之后回扫**：再扫一遍「之前被标记为不可种」的格子（R4.2 那类），
  可种就种、不可种保持标记。
- **R5.6** 回到 R5.1，等下一个 3 小时。

## 6. 「不可种」标记的全局规则（R6，最重要）

- **R6.1** 任何扫描（主扫描 / 升级回扫 / 弱扫描补种 / 补种后回扫）中，**判定失败的格子必须被标记**，
  一条都不能漏。
- **R6.2** 判定成功并种下的格子，**立刻从标记集合中移除**。
- **R6.3** 标记集合**随存档保存**（与编号一起），元素为格坐标。
- **R6.4** 标记格只在两个时机被重新判定：① 升级回扫（R4.2）② 弱扫描补种后的回扫（R5.5）。
- **R6.5** 标记只表示「上次判定的结论」，不允许用标记去替代判定（每次仍要按 R2 重新判）。

## 7. 数值（已定稿，不得擅自修改）

| 项 | 值 |
|---|---|
| R7.1 速度（每株） | 一档 **15 秒**、二档 **8 秒**（进阶功能花后）、三档 **1 秒**（终极功能花后） |
| R7.2 收成系数 | 一档 **×0.50**、二档 **×1.00**、三档 **×1.50** |
| R7.3 半径 | 基础 **5**，进阶 **+1**、终极 **+1** → 5 / 6 / 7 |
| R7.4 播种 / 收获魔力 | **12 / 6** 每株 |
| R7.5 花瓣 | 每 **7** 次播种耗 **1** 片；仓容 75，走 `CompRefuelable`（小人自动搬） |
| R7.6 催熟 | 固定 **1000 魔力**、冷却 **180 tick**、半径内所有非树植物、已成熟直接收获、未成熟 +0.30 |
| R7.7 夜间取木 | 每棵 3 原木、最多 30 棵、0 点触发、不耗魔力但要求网络有魔力、同一棵树每夜只算一次 |

## 8. 明确禁止（防跑偏）

- **禁止**用随机选格替代编号顺序。
- **禁止**用「队列 + 游标 + 定时重建」之类的优化替代本规则描述的扫描流程。
- **禁止**引入 Harmony 补丁或事件驱动改造来替代本规则（不是不允许 Harmony，而是**本规则不依赖它**）。
- **禁止**擅自改动第 7 节的任何数值。
- **禁止**把「不可种标记」当成永久结论跳过判定。

## 9. 验收清单（可执行断言）

1. 建造/重装/研究完成时，编号被重建（N 与半径对应：5→N1、6→N2、7→N3）。
2. 主扫描严格按编号顺序种；同一轮内每格只判定一次。
3. 格上有草 / 野花 / 野果灌木 / 野生作物 → 被割除且有产出时给产物（按档位系数），随后同格种下。
4. 格上有建筑 / 树 / 人工种植的植物 → 不割除、标记不可种、跳过。
5. 第 N 格可种时必须种完才进入升级检查。
6. 升级后回扫「旧标记格 + 新增格」，然后重新编号。
7. 弱扫描每 7500 tick 触发；范围不一致时重编号并回主扫描。
8. 弱扫描先逐格收、收完再补种、补种后再回扫标记格。
9. 所有扫描路径的判定失败格子都被标记（抽查：人为放一堵墙在标记格上，升级回扫时该格仍标记）。
